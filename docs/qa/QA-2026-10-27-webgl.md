# Rapport QA — premier test du build WebGL (2026-10-27)

Build testé : `QaBuild/Build` (Development Build, sans compression, sans le symbole `CONTIGU_DEBUG`), ouvert avec `?qa=1` dans Chromium sans écran (rendu logiciel).

## Résumé

Le crochet de test (`QaBridge`) a fonctionné dès le premier essai : état de l'écran, clics, survols. Trois parcours de bout en bout passent, sans erreur du jeu dans la console :

| Parcours | Résultat |
|---|---|
| Menu → Collection (4 onglets, 0/253) → Close → Play → choix du défi → partie | OK |
| Guide de Sprig → 43 placements de graines aléatoires légaux (manches 1 et 2, défaite en manche 2 : normal pour un joueur aléatoire) | OK |
| Boutique : survol de chaque objet (tooltips), achat de fertilizers, Sprout Pack / Mastery Pack, choix de graines (« Select 3 seeds » + Confirm), « Leave », manche 2 | OK |
| Menu → Save & quit → Play → Continue : manche, Pollen, shuffles et fertilizers identiques avant/après | OK |

Aucun bug du jeu n'a été trouvé dans ces parcours. Les observations ci-dessous sont des points de clarté et d'équilibre, à juger.

## Observations

1. **Le guide de Sprig demande 13 à 14 clics** pour être fermé (« It only takes a moment »). Un joueur impatient n'a pas de bouton « Skip » visible dans l'état publié (le seul bouton cliquable est le guide lui-même). À vérifier à l'écran : si un « Skip » existe, il n'est pas exposé comme bouton. — Clarté, Suspecté.
2. **Les prix de la boutique montent vite après chaque achat** : après 3 fertilizers, le Sprout Pack passe de 5 à 12, le Fertilizer Pack de 6 à 15, Compost de 3 à 8, la Forge de 4 à 10 (capture `hover-UpgSlot_0`). C'est voulu (`ShopPriceEscalationPerPurchase`) mais rien à l'écran ne dit que les prix montent. — Clarté, Confirmé.
3. **La main passe d'une manche à l'autre** : en manche 2, la main contenait 1 graine et 2 emplacements vides (reste de la manche 1). Voulu (la main ne se redistribue qu'une fois vide), mais déroutant sans explication. — Clarté, Confirmé.
4. **Menu principal au chargement** : pendant la première seconde, les boutons sont assombris et ne reçoivent pas de clic (le fondu d'entrée). Normal, noté seulement.

## Limites de ce test

- **Bruit d'environnement, pas des bugs du jeu :** Chromium sans écran n'a pas les codecs audio ; les sons (`Whoosh`, `ButtonClick`, `Score`…) échouent à décoder. La console de développement d'Unity affiche alors ces erreurs en rouge dans le coin bas-gauche des captures. Le harnais les écarte du verdict (`environmentNoise`).
- **Sans `CONTIGU_DEBUG`**, les commandes de triche (`forceRoundWin`, `grantPollen`) sont refusées : les parcours jouent les manches pour de vrai (lent et aléatoire). Avec le symbole, la boutique est atteinte tout de suite et on peut y mettre beaucoup de Pollen.
- Rendu en logiciel (SwiftShader) : les animations sont plus lentes qu'à l'écran d'un joueur, aucun jugement sur la fluidité.
- Non couvert : drag & drop des graines, tooltips en jeu pendant le décompte, tous les écrans de fin (victoire, défaite), Endless, les 5 autres défis, l'ordre d'affichage du décompte (ma passe de revue de code l'a couvert, pas ce test).

## Prochaines étapes suggérées

1. Refaire le build avec `CONTIGU_DEBUG` pour tester les cas rares (boutique pleine, packs, Endless, défaite) sans jouer à la main.
2. Ajouter des scénarios pour les ennemis (verrous, poison, glace) en choisissant les défis Marathon (Hoarfrost) et Orchard.
