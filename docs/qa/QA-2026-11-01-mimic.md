## 1. Résumé

Exécuté :
- `cd Tools/Headless/Tests && dotnet test` : 638/638 verts (aucun test ne couvre les cas ci-dessous).
- `content_audit.py` : 0 trouvaille (73 sprouts, 77 traits). `check_icon_tags.py` : OK. `glyph_audit.py` : 1 ligne hors sujet (`…` dans `UITweaks.cs:33`, pas lié à Mimic).

Deux problèmes de fond : la réutilisation de l'id sauvegardé 76 (nouveau, causé par Mimic) et l'écrasement du trait de combat d'un Joker par un sprout (ancien, mais Mimic en hérite). Le reste est de la clarté.

Trouvailles : Bloquant 0, Majeur 2, Mineur 2, Clarté 4, Observation d'équilibre 2.

Rien de visuel n'est vérifié en jeu (Unity ne tourne pas) ; tout constat de présentation est « d'après le code ».

## 2. Trouvailles

### T1 [Majeur, Confirmé] `PieceTraitKind.Mimic` réutilise l'id 76, celui de Sangsue (Sap Drain) retiré

- Où : `Assets/Scripts/Core/Pieces/PieceTrait.cs` (Mimic = 76 car Sangsue, dernier membre, a été supprimé en 6990180) ; `RunSnapshot.cs:205-217` (`TokenFromText`) ; `Tests/EditMode/RunSaveTests.cs:212` (l'id « inconnu » du test est passé de 76 à 200 dans aa49e4f, ce qui masque le problème). CLAUDE.md : « ne jamais supprimer un membre d'enum ».
- Reproduction (test jetable `mq/T4.cs`) : prendre `RoundStartSnapshot.ToText()`, remplacer `deck=` par `deck=<Single>,<Joker>,76.0.-1;`, `RunManager.Restore(RunSnapshot.FromText(...))`. Résultat observé : le Joker a `Bombe@0 Mimic@0` (deux upgrades sur la même case 0). Avant aa49e4f, le 76 était ignoré et le Joker recevait seulement Bombe.
- Attendu : un save contenant l'ancien Sangsue (Joker, id 76) ne doit pas devenir un Mimic. Les saves du jeu publié entre l'ajout de Sangsue et son retrait contiennent des 76.
- Impact : Joker avec Mimic parasite sur une case déjà occupée (deux badges sur la même case), possible Mimic « gratuit » sur une graine non-Joker issue d'un vieux save (76 sur une graine normale devient un Mimic). Touche seulement les parties sauvegardées avec un Joker Sangsue, donc limité mais silencieux.
- Piste : donner à Mimic un id neuf (77, en laissant 76 retiré et ignoré) ou convertir explicitement 76 à la reprise ; remettre 76 comme id « retiré » dans le test.
- Même risque pour `UpgradeId` : `MimicTile` = 89, rien ne réutilise d'id ici (RAS).

### T2 [Majeur, Confirmé, pré-existant mais Mimic en hérite] Un sprout posé sur un Joker à une seule case écrase son trait de combat

- Où : `DeckManager.TagSpecificTokens` (`DeckManager.cs:777-808`, branche « aucune case libre » -> `ReplaceTraitOnCell`) ; `UpgradeSystem.GetCandidateTilesFor` (`UpgradeSystem.cs:243-254`) n'exclut les Jokers que pour Tinted.
- Reproduction : `mq/T5.cs` : ajouter `PieceToken(Single, Joker, Bombe@0)` au sac, `TagSpecificTokens(idx, Mimic)` -> trait final `Mimic@0` seulement ; `GetCandidateTilesFor(MimicTile, ...)` propose bien ce Joker. Fuzz : `cd Tools/Headless/RunSim && PLAN_DEPTH=2 dotnet run --no-build -- --runs 1 --policy planner --challenge Classic --check --endless --seed 15` -> `invariant: A Joker seed has 0 combat traits (it must have exactly 1): Single [round 34]`. Aussi `dotnet run --no-build -- --each --runs 8` : 12 sprouts nommés (Gardener, Cluster, Sower, Wildroot, Glow...) ; le même `--each` sur le parent en nommait 10, donc pas une régression de Mimic.
- Attendu : « un Joker garde son trait de combat pour de bon » (`DeckManager.cs:506`, Transplant) ; l'invariant du simulateur le dit aussi.
- Impact : le joueur perd le trait de combat d'un Joker (Bombe/Range/Eclat/Precision) en y mettant un sprout (Mimic compris, qui n'a alors rien à copier de plus). Mimic a un risque en plus : sur un Joker `Single` il remplace le combat par une upgrade qui ne fait rien sans voisin.
- Piste : exclure des candidats (et refuser dans `TagSpecificTokens`) les Jokers dont toutes les cases sont prises.

### T3 [Mineur, Confirmé] Mimic est sans effet sur plusieurs upgrades que son texte laisse croire copiables

- Où : `RunManager.TileUpgrades.cs:148-151` (`IsMimicCopyable`) + `ApplyPostPlacementTraitBonus` (`RunManager.Traits.cs:345-430`).
- Reproduction : `mq/T.cs` (matrice) : Mimic voisin de Sower, Gap, Wildroot, Bridge, Evergreen, Chameleon, Seeder -> 0 point, aucun effet (leurs effets sont des drapeaux ou se résolvent avant le score). Kamikaze voisin : le Kamikaze se détruit lui-même et détruit le Mimic (voisinage de Moore) avant que Mimic ne lise (`TraitAsPlaced` rend null sur une case détruite) : bilan 12 pts seulement, jamais de copie. Constaté aussi : Mimic copie Bastion (verrouille sa propre case) et Void (efface une 2e case au hasard).
- Attendu : texte « copie l'upgrade de chaque voisin ». DECISIONS.md ne mentionne que Golden/Tinted/Multiplier/Blast/Beacon comme non copiés, pas Sower/Gap/Wildroot/Bridge/Evergreen/Chameleon/Seeder.
- Impact : achat qui semble bon et ne fait rien ; combos Kamikaze/Sower sans retour.
- Piste : soit les exclure explicitement de `IsMimicCopyable` et le dire, soit corriger le texte.

### T4 [Mineur, Suspecté (lecture de code)] Les copies sans points ne font pas pulser le badge du Mimic

- Où : `GameBootstrap.Placement.cs:644-651` : le badge ne pulse que sur un `ScoreEvent` de type Trait à la position de la case. Les copies de Warden, Glow, Locksmith, Dye, Fertile, Seedpod, Venom, Void n'ajoutent aucun événement à la position du Mimic (les événements de monde sont rejoués après le décompte via `PlayTileUpgradeWorldEffects`, `PlayVenomHits`, etc.). Le joueur voit l'effet (tuiles, ciel, ennemi) sans voir que c'est le Mimic qui l'a produit.
- Pour confirmer : build WebGL + capture d'un Mimic voisin d'un Locksmith/Glow. Non vérifié en jeu.

### T5 [Clarté] Deux « Mimic » : le fertilizer `Copieur` s'affiche « Mimic », le sprout s'appelle « Mimic Sprout »

- Où : `ModifierDefinition.cs:329` (`"Mimic"`, copie le fertilizer acheté juste avant), `UpgradeDefinition.cs:479` / `PieceTraitVisualDefaults.cs:113`. GLOSSARY.md liste les deux (lignes 82 et 147) sans les distinguer. Deux noms voisins pour deux mécaniques de copie différentes (tooltip, collection, achats).
- Piste : renommer l'un des deux, ou ajouter une phrase de distinction dans le texte du sprout.

### T6 [Clarté] Le texte ne dit pas ce qui est exclu, ni où la copie est évaluée

- Texte actuel : « Copies the upgrade of every tile of its group touching it, as if it carried them itself. » (+ « Counts again every time this tile is scored. »).
- Non dit : (a) n'agit que si le voisin orthogonal est dans le groupe marqué ; (b) ne copie ni Mimic, ni Amplifier, ni Echo ; (c) les conditions de position sont évaluées sur la case du Mimic (Border/Corner/Heart/Keystone/Crossfire/Hermit... : copier un Corner voisin donne 0 sauf si le Mimic est lui-même dans un coin ; Cuddly/Companion comptent les voisins du Mimic) ; (d) les compteurs de Growth sont ceux de la case du Mimic, pas ceux du voisin (`growthCell = Grid.GetCell(pos)`), et Perennial incrémente le compteur global de la manche/run une fois de plus par copie ; (e) l'aléa est retiré indépendamment (Lucky, Gambler : deux jets distincts).
- Piste : une phrase courte + une ligne dans BALANCE.md ; ajouter une entrée de tutoriel/Sprig si les sprouts de copie y figurent.

### T7 [Clarté] Aucun signal quand un Mimic n'a rien à copier

- Un Mimic seul, ou voisin de sprouts non copiables, ne marque rien (pas de badge qui grise, pas de message) ; le sélecteur de tuile (`TileChoiceView`) ne prévient pas que Mimic ne sert que dans un groupe avec d'autres upgrades.

### T8 [Clarté] Couverture de tests mince

- Un seul test (`TileUpgradeTests.Mimic_...`) : Pip/Mimic/Amplifier. Manquent : Mimic « ancien » dans un groupe agrandi (j'ai vérifié à la main : P3/P4 de `mq/T7.cs` donnent +1 par Pip copié, y compris Mimic entre deux Pips), Seedpod/Fertile/Spillover sur case récoltée (j'ai constaté 4 tuiles semées au lieu de 2), effets modifiant la grille, sauvegarde d'un vieux id 76 (T1).
- Invariants proposés pour `Invariants.cs` : (1) aucune case de la grille ne porte deux traits de même `LocalCellIndex` ; (2) pas de trait d'upgrade dont l'id n'est pas dans `UpgradeCatalog` (attrape T1) ; (3) un Joker ne perd jamais son trait de combat entre deux actions de boutique (déjà vérifié, T2).

### T9 [Observation d'équilibre] Mimic dépasse Amplifier/Echo en largeur, sans plafond

- Faits mesurés (`mq/T.cs`, `T2.cs`) : Mimic + Pip = +2 ; Mimic entre deux Pips = +2 (une copie par voisin) ; Mimic + Detonator sur ligne récoltée : 18 + 18 (le doublement est recopié, TraitBonus 36 vs 19) ; Mimic + Spark : 20 + 20 ; Mimic + Gambler : 40 + 40 (pile) ; Mimic + Breeze : 2 x 1437 avec 500 shuffles (valeur de test) ; Mimic + Seedpod récolté : 4 tuiles semées ; Mimic + Dewdrop/Honeycomb : Pollen doublé. Amplifier ne double que les points ; Mimic copie aussi Pollen, Mult (Keystone, si bien placé), pouvoirs de grille et chaînes (Amplifier/Echo voisin du Mimic lisent ensuite sa copie : voulu d'après DECISIONS.md).
- Raretés : Mimic et Amplifier Rare, Echo Uncommon. Mimic est plus généraliste qu'Amplifier ; il peut être tenu pour trop fort avec Detonator/Spark/Gambler/Seedpod, sans plafond (4 voisins max par Mimic, mais plusieurs Mimic autour d'un même sprout cumulent).
- Simulateur : planner profondeur 2, Classic, 200 runs, seed 100 : 10,5 % de victoires (parent : 12,0 %, même commande) ; écart non significatif (le flux RNG change avec le pool). Pas de signal fiable pour juger la puissance de Mimic ; il faudrait suivre « Mimic présent dans le sac » sur les victoires (non fait).

### T10 [Observation] Ordre de résolution dépendant du hasard et de la grille

- Les copies de Void/Kamikaze/Pruner/Dye détruisent ou repeignent des cases lues ensuite par un autre Mimic ou Amplifier (`TraitAsPlaced` rend null sur une case détruite) : un second Mimic voisin peut perdre sa copie selon l'ordre de `GroupCells`. Pas un plantage ; fuzz sans erreur. À garder en tête si l'on ajoute un test d'ordre.
